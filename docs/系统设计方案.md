# AI 八字命术系统 · 系统开发设计方案

> 版本：v1.0
> 定位：Web 应用 · 八字为核心 · 规则引擎负责排盘 · AI 仅负责自然语言解读
> 性质声明：本产品属于传统文化与娱乐范畴，不构成医疗、投资、法律等任何专业建议。

---

## 1. 项目概述

### 1.1 产品定位
通过用户的出生时间与出生地点（经纬度，作为"空间/磁场"的可计算代理变量），由**确定性规则引擎**完成八字排盘，再由**大模型**把结构化结果翻译成通俗易懂的命理解读报告。

核心原则：
- **算法负责"准"**：排盘、五行、大运流年全部由可测试的纯函数计算，结果确定、可复现。
- **AI 负责"讲"**：大模型只接收引擎算好的结构化结果，禁止自行排盘，避免幻觉。
- **合规优先**：全程带娱乐免责声明，不做确定性断言，敏感数据加密可删。

### 1.2 目标用户
- 对传统命理文化感兴趣的普通用户
- 希望快速排盘并获得白话解读的爱好者

### 1.3 不做的范围（v1）
- 紫微斗数、风水、六爻等其他流派（后续可扩展）
- 医疗/投资/法律等高风险确定性建议
- 移动端原生 App（先做响应式 Web）

### 2.2 分层职责

| 层 | 职责 | 关键约束 |
|---|---|---|
| 前端 | 交互、录入、可视化、报告展示 | 不做任何命理计算 |
| API 网关 | 鉴权、校验、编排、限流 | 统一错误码与响应结构 |
| 排盘引擎 | 全部命理计算，纯函数 | 无副作用、可单测、可复现 |
| AI 解读服务 | 结构化结果 → 白话报告 | 输入必须来自引擎，禁止自行排盘 |
| 数据服务 | 账户、命盘存储 | 出生数据加密、可删除 |

## 4. 核心模块设计

### 4.1 排盘引擎（项目地基，最先打磨）

独立包 `@app/bazi-engine`，纯函数、无 I/O、100% 可单测。

#### 4.1.1 输入
```typescript
interface BirthInput {
  calendar: 'solar' | 'lunar';   // 公历 / 农历
  year: number;
  month: number;
  day: number;
  hour: number | null;           // null = 时辰未知
  minute: number | null;
  gender: 'male' | 'female';
  longitude: number;             // 出生地经度，用于真太阳时
  latitude: number;
  useTrueSolarTime: boolean;     // 是否启用真太阳时校正
}
```

#### 4.1.2 计算流水线
1. **历法换算**：公历 ⇄ 农历互转。
2. **节气计算**：二十四节气（用天文算法，决定月柱边界）。
3. **真太阳时校正**：经度时差 + 均时差，把钟表时间换算为真太阳时。
4. **四柱排盘**：年柱、月柱、日柱、时柱的天干地支。
5. **藏干 / 十神 / 纳音**。
6. **五行统计**：数量、旺衰、喜用神 / 忌神。
7. **大运排布**：起运年龄、顺逆、每步十年干支。
8. **流年 / 流月**推算。
9. **神煞**（可选扩展）。

#### 4.1.3 输出（结构化结果，喂给 AI）
```typescript
interface BaziChart {
  pillars: {
    year:  Pillar;
    month: Pillar;
    day:   Pillar;   // 日主
    hour:  Pillar | null;
  };
  fiveElements: {
    counts: Record<Element, number>;
    dayMasterStrength: 'strong' | 'weak' | 'balanced';
    favorable: Element[];    // 喜用神
    unfavorable: Element[];  // 忌神
  };
  luckCycles: LuckCycle[];   // 大运
  currentYear: YearFortune;  // 当前流年
  shensha?: string[];
  meta: {
    trueSolarTimeApplied: boolean;
    hourKnown: boolean;
  };
}

interface Pillar {
  heavenlyStem: string;   // 天干
  earthlyBranch: string;  // 地支
  hiddenStems: string[];  // 藏干
  tenGod: string;         // 十神（相对日主）
  naYin: string;          // 纳音
  element: Element;
}
```

#### 4.1.4 测试策略
- 用**权威命理软件/古籍案例**建立黄金测试集（≥ 50 个已知命盘）。
- 节气边界、跨年立春、子时换日、闰月等**边界用例**必须覆盖。
- 真太阳时校正单独验证（用已知经度对照）。

### 4.2 AI 解读服务

#### 4.2.1 工作方式
- 输入 = 排盘引擎的 `BaziChart`（结构化）+ 检索到的命理规则片段（RAG）。
- 输出 = 分维度自然语言报告 + 追问式问答。
- **硬约束**：Prompt 中明确"以下排盘结果为准，不得重新计算或修改任何干支/五行数据"。

#### 4.2.2 RAG 知识库
- 内容：十神含义、五行生克、格局判断、大运流年解读口诀等结构化命理知识。
- 检索：按盘面特征（十神组合、旺衰、格局）召回相关规则，减少幻觉。

#### 4.2.3 报告维度
性格特质 · 事业 · 财运 · 感情婚姻 · 健康提示 · 六亲关系 · 大运流年走势。

#### 4.2.4 输出规范
- 流式返回（提升体验）。
- 每份报告附免责声明。
- 时辰未知时，时柱相关维度自动降级说明或省略。
- 禁止：疾病诊断、寿命断言、投资/买房等确定性指令。

### 4.3 前端模块
- **录入向导**：分步表单，城市选择器带经纬度，真太阳时开关，时辰未知选项。
- **命盘可视化**：四柱表（干支/十神/藏干，五行配色）、五行雷达图、大运流年时间轴。
- **报告展示**：分维度卡片，可展开细节，流式渲染。
- **命盘问答**：对话式追问，带盘面上下文。
- **账户中心**：命盘列表、多档案（家人）、数据导出/删除。

### 4.4 用户与数据服务
- 账户：注册/登录（邮箱 + JWT）。
- 命盘存储：出生信息（敏感字段加密）、排盘结果缓存、报告历史。
- 多档案：一个账户管理多个人的命盘。
- 数据权利：一键导出、软删除 + 物理删除。

## 5. 数据模型（核心表）

```
users
  id, email, password_hash, created_at, deleted_at

profiles            -- 命盘档案（可多个）
  id, user_id, name, gender,
  birth_calendar, birth_datetime_enc (加密),
  longitude, latitude, hour_known,
  use_true_solar_time, created_at, deleted_at

charts              -- 排盘结果缓存
  id, profile_id, engine_version,
  chart_json (排盘结构化结果), created_at

reports             -- AI 解读报告
  id, chart_id, dimension, content,
  model_version, created_at

knowledge_chunks    -- RAG 命理知识
  id, topic, content, embedding (vector)
```

关键点：
- `birth_datetime_enc` 加密存储（应用层加密）。
- `engine_version` / `model_version` 记录版本，便于结果复现与回归。
- 排盘结果缓存，相同输入不重复计算。

## 6. API 设计（REST 示例）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/register` | 注册 |
| POST | `/api/auth/login` | 登录 |
| POST | `/api/profiles` | 新建命盘档案 |
| GET | `/api/profiles` | 档案列表 |
| POST | `/api/charts/calculate` | 排盘（调用引擎，返回结构化结果） |
| POST | `/api/reports/generate` | 生成 AI 解读（流式） |
| POST | `/api/reports/ask` | 命盘问答（流式） |
| DELETE | `/api/profiles/:id` | 删除档案与关联数据 |

统一响应结构：
```json
{ "code": 0, "message": "ok", "data": {} }
```

## 7. 合规与安全

| 项 | 措施 |
|---|---|
| 免责声明 | 首页、报告头尾显著展示"文化娱乐用途" |
| 内容边界 | 禁止医疗诊断、寿命/投资等确定性断言（Prompt + 后处理双重过滤） |
| 数据加密 | 出生时间等敏感字段应用层加密，传输 HTTPS |
| 数据权利 | 用户可导出、可删除全部数据 |
| 访问控制 | JWT 鉴权，档案级权限校验 |
| 限流 | Redis 限流，防止 LLM 接口被刷 |
| 密钥管理 | LLM API Key 等走环境变量/密钥管理，不入库不入前端 |

## 10. 风险与注意事项

- **节气/真太阳时精度**：直接决定月柱、时柱正确性，是准确性风险最高点，必须自建校验。
- **AI 幻觉**：严格约束"以引擎结果为准"，配合 RAG 与后处理过滤。
- **合规风险**：避免涉医涉资断言，全程免责声明。
- **数据隐私**：出生信息属敏感个人信息，加密与删除机制不可省。
- **流派争议**：同一盘不同流派结论不同，v1 只做八字，口径保持"仅供参考"。
